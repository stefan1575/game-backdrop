# Domain docs

Before exploring code, read `GLOSSARY.md` at the repo root and any decisions in `docs/adr/`
that touch the area you're about to work in. These are optional: if absent, continue without
creating them just to fill the layout.

Use the glossary's terms when naming domain concepts in issues, proposals and tests. If a term
is missing, check the code's vocabulary before proposing a new one.

If a proposal contradicts an existing ADR, name the ADR and explain why it should be reopened.
